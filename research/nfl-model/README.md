## The collection contract (injury + depth)

Injury and depth data is the part of this project that produced the most irregularities, so
the contract is fixed here rather than rediscovered per run.

1. **Sources.** Injuries: `https://www.nfl.com/injuries/` (live) and
   `https://www.nfl.com/injuries/league/<season>/REG<week>` (archived, one page per week,
   grouped per game). Depth: `https://www.<club>.com/team/depth-chart` — the league does not
   publish depth charts (`nfl.com/teams/<club>/depth-chart` returns 404; see IR-028).
   Transactions: `nfl.com/teams/<club>/transactions` also 404s; use the club site.
2. **Render-integrity assertion before any parse.** `check_injury_structure()` refuses a
   snapshot unless the page contains ≥4 `Game Status` column headers and ≥8 player links, and
   the club-set row counts are within a factor of 2 of the previous week. A partially rendered
   official page looks exactly like a quiet injury week; that trap has already fired once
   (Week 10 fetched four times: 30 rows → 162 rows → 0 rows). The 162-row capture exists only
   in this session's transcript — it is **not** in `nfl-model/data/injuries.json`, because a
   section must not publish a row it cannot re-derive from a stored artifact.
3. **Club attribution.** Rows must be grouped under the club block that actually lists them.
   On a per-game view, verify each row's team before assigning a label: a "no designation"
   signal attributed to the wrong club is worse than no signal (IR-033 render integrity, IR-034 coverage).
4. **Blanks are data.** `Injuries` and `Game Status` come back empty for many listed players,
   and the league's own rules explain why: a player certain to play is omitted from the game
   status report by design. Blanks are rendered as `not confirmed`; they are never inferred
   from a third-party site. A missing designation is therefore *not* a probability input.
5. **Coverage accounting.** Any table of "the official injury report" must publish which clubs
   were captured and which were not, in the same table. 1 of 32 clubs structured is stated as
   1 of 32, not presented as a league-wide view.
6. **Depth join states.** A depth row and an injury row are different objects and must not be
   collapsed: the chart can list a starter the report marks inactive (or omit a reported
   player entirely). Each published depth row keeps the club's own `Updated as of` date.
7. **Nothing crosses into the free-time product.** The dashboard's rows come from
   `data/official/**` and `scripts/collect_official.py`; this section writes only
   `nfl-model/**`, `research/nfl-model/**` and its own scripts.

## Refresh cadence

| Dataset | When | Note |

| Club depth charts | once daily | carries its own update date |
| Colorado handle/tax | monthly release | figures get revised; retrieve the revision too |
| New Jersey monthly | monthly release | PDF; the handle/parlay table is a later chunk than the headline figures |
| Odds feed | on demand | needs an API key; the collector never stores the key in the repo |

## Flag numbering

The root dashboard and the merged `nfl-*` NFL module publish `IR-001…IR-026` on
`flagged.html`; the `nfl-decision-*` section keeps its own `FL-01…FL-06`. **This section
continues the shared `IR` sequence at `IR-027` and runs through `IR-041`**, so no id is ever
doubled up across the site and a reader quoted an id gets one meaning. The verifier enforces the
floor (`flagged.json: <id> collides with the root pages' IR-001..IR-026 range`).
